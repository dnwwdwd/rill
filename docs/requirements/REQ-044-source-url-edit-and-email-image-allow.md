# REQ-044: 订阅地址编辑与邮件图片放行持久化

> 状态：已实现（本地验证；真实浏览器/邮箱待验收） · 日期：2026-11-23

## 背景

用户补充两点行为：

1. 邮件正文的远程图片一旦被放行，或放行了该发件人的图片，之后都应持续显示图片，而不是每次重新打开都回到拦截状态。
2. 编辑订阅源弹窗需要允许修改订阅地址；修改后自动更新相关元数据并重新抓取文章内容。

## 范围与行为

### 1. 邮件图片放行持久化

- 「显示图片」从一次性放行改为按邮件条目持久化：点击后写入该条目的 `media_json.email_images_allowed=true`，详情接口返回 `email_images_allowed`；之后打开同一邮件不再显示拦截提示。
- 「始终显示此发件人的图片」保持原有按发件人持久化：发件人地址写入 `settings.email.trusted_senders`，后续该发件人的邮件自动显示图片。
- 关闭「拦截远程图片」仍等同于全部放行。
- 不新增表或列；复用 `items.media_json` 扩展字段。

### 2. 编辑订阅地址

- 设置 → 订阅源 → 编辑弹窗新增「订阅地址」。邮箱同步源（`imap://`）不显示该项，地址由「邮箱同步」账号配置管理。
- 保存时若地址发生变化：
  - 按源类型校验地址并做大小写不敏感的重复检查。
  - 清空 ETag、Last-Modified、图标缓存与失败状态，重置首次抓取标记，并标记需要刷新元数据。
  - 立即抓取新地址；抓取成功后，源名称（同一次请求未显式改名时）、站点地址和图标跟随新 Feed 更新。
  - 已有条目保留，新 Feed 的条目按既有去重键入库。

## API

- `PATCH /api/v1/items/{id}/email-images`，body `{"allowed": true|false}`；仅邮件源条目的 `allowed=true` 有 UI 入口。
- `PATCH /api/v1/sources/{id}` 新增可选 `feed_url`。邮箱同步源返回 `invalid_source`。

## 数据与配置

- `items.media_json` 增加 `email_images_allowed`，无 schema 迁移。
- `sources.config_json` 在地址变更后临时写入 `refresh_metadata` / `refresh_metadata_name`，成功抓取后清除。
- 无新增依赖。

## 验收

1. 打开一封被拦截远程图片的邮件，点击「显示图片」，关闭再打开同一邮件时图片直接显示。
2. 点击「始终显示此发件人的图片」后，该发件人的新邮件直接显示图片。
3. 编辑普通 RSS/Atom 源的订阅地址并保存，源名称、站点地址、图标和文章列表随新 Feed 更新。
4. 改成已订阅地址时提示重复；改成非法地址时提示无效；邮箱同步源不提供地址编辑。
5. 新地址抓取失败时保留原条目并显示抓取失败原因，不把保存操作报成成功更新内容。
