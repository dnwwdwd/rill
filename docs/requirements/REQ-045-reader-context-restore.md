# REQ-045: 刷新后恢复订阅源与文章阅读上下文

> 状态：已实现（本地验证；真实浏览器待验收） · 日期：2026-11-23

## 背景

用户刷新或重新打开 Rill 后，列表默认回到「全部」，即使刚才正在看某个订阅源；正在阅读的文章虽然位于 `/items/{id}`，列表上下文也会丢失。用户要求刷新后默认展示之前打开的订阅源和浏览的文章，并保证路由仍指向之前的页面。

## 行为

- 记住最近选择的阅读筛选：全部、未读、收藏、稍后读、已读、单个订阅源、分组。
- 记住已读状态筛选（全部/未读/已读）。
- 记住最近打开的文章 ID。全量刷新且初始路由为 `/` 时，自动重定向到 `/items/{id}`（`replace`，不新增历史记录）；如果该文章已不存在，停留在列表。
- 回到 `/items/{id}` 刷新时，文章路由保持不变，列表恢复之前的订阅源/分组。
- 只在一次完整页面加载中恢复一次；应用内点击订阅源返回 `/` 时不会被强制跳回上一篇文章。
- 若记住的订阅源/分组已被删除，自动回退到「全部」。
- 退出登录或会话过期时清除这些本地记录。

不持久化搜索词、已保存视图之外的多选状态或滚动位置。

## 实现

- `web/src/utils/readerPersistence.ts`：localStorage 键 `rill.reader.filter.v1`、`rill.reader.readFilter.v1`、`rill.reader.lastItem.v1`，读取时校验类型与正整数 ID。
- `readerStore` 初始状态读取持久化筛选；`setFilter` / `setReadFilter` 写入；`loadDetail` 成功后记录文章 ID；`reset` 清除。
- `ReaderPage` 首次挂载且 URL 无文章 ID 时，读取最近文章并 `loadDetail` 校验后重定向；源/分组加载完成后校验筛选对象是否仍存在，不存在则回退到「全部」。

## 验收

1. 打开某个订阅源，选中一篇文章，刷新浏览器：仍在 `/items/{id}`，左侧列表仍是该订阅源。
2. 在 `/` 刷新：若上次浏览过文章，自动回到该文章路由；左侧列表仍是上次的订阅源/分组。
3. 点击侧栏「全部」或其他订阅源时，即使上次看过文章，也停留在列表，不自动跳文章。
4. 删除当前选中的订阅源后刷新，自动回到「全部」，不显示空列表。
5. 退出登录后重新登录，不恢复上一账号的筛选或文章。
