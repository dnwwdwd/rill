# REQ-036 定时报告与可配置推送渠道

- 状态：进行中（后端完成本地验证，前端进行中；见 DEC-027）
- 日期：2026-11-10
- 关联：PRD F-50、PDD §4/§5/§9、DEC-027

## 目标

定时汇总指定订阅源在一个时间窗口内的文章，用 AI 生成一份可读的报告；报告保存在应用内可随时查看，并按规则配置推送到外部渠道（飞书机器人、自定义 webhook）。飞书只是渠道之一，不是唯一展示形式。

## 范围

1. 报告规则：名称、范围（选定源 / 分组，空 = 全部源）、周期（每天 / 每周 + 本地时间点）、启用开关、推送渠道（多选）。
2. 报告生成：窗口为「上次运行 → 本次运行」（首次运行为 24h/7d 回溯窗口）；范围源内该窗口发布的条目。
3. AI 摘要策略：已有单条 AI 摘要的直接复用缓存；没有的按批（每批 ≤8 条，标题 + 正文节选 ≤800 字）先生成分条小结，再合并为一份 Markdown 报告；合并层批小结超过 ~40 条时树状归并（先归并成组再终合并），保证合并调用输入有界；AI 未启用或失败时降级为纯列表（标题 + 来源 + 时间 + 链接）推送，状态标 `partial`/`error` 语义见 DEC-027。
4. 报告落库：Markdown 全文存 `digest_reports`，应用内可查看（Markdown 渲染）。
5. 上下文与成本保险：单次报告条目上限默认 200，超出时只取最新 200 条并在报告开头标注「窗口内共 N 条，已截取最新 200 条」；历史回补的旧条目（发布时间在窗口外）天然不进入报告。
6. 推送渠道：飞书机器人 webhook（interactive 卡片，Markdown 正文）；自定义 webhook（POST JSON）。webhook URL 属凭据，加密存储，接口只返回打码形式。
7. 推送语义：生成成功后自动推送；失败可手动重推；无新内容时按规则配置决定是否生成「空报告」（默认不生成、不推送）。
8. 手动触发：规则可「立即生成」一次报告，不影响后续周期。
9. 范围支持按分组（文件夹）选：`scope_json` 可含 `folder:<id>` 条目，文件夹后续新增源自动纳入；具体源与分组可混选。

## API

- `GET/POST /api/v1/digest/rules`、`PUT/DELETE /api/v1/digest/rules/{id}`
- `POST /api/v1/digest/rules/{id}/run`（手动生成）
- `GET /api/v1/digest/reports?rule_id=&limit=`、`GET /api/v1/digest/reports/{id}`
- `POST /api/v1/digest/reports/{id}/push`（重推）
- `GET/POST /api/v1/channels`、`PUT/DELETE /api/v1/channels/{id}`、`POST /api/v1/channels/{id}/test`

## UI

设置弹窗新增「自动化」分类：报告规则列表与编辑、推送渠道管理（含发送测试）、报告列表（点开查看 Markdown、显示推送状态、可重推）。范围树的父节点与子节点双向联动：勾选分组即包含组内全部源，取消任一子源会自动展开为单源选择；切换「自定义」时预选全部分组与未分组源。渠道编辑支持「保存并测试」直接发送测试通知。规则行提供「查看报告」入口；报告始终保存在应用内，与是否配置推送渠道无关。`run_at_local` 按部署时区（`RILL_TIMEZONE`，默认 `Asia/Shanghai`）解释；飞书只推送极简简报，完整报告与文章清单在 Rill 内查看。

## 验收

- 本地建规则（每天某时刻），窗口内有新文章时生成报告并落库；无新文章不生成。
- AI 启用时报告为分条小结 + 总述；AI 关闭/失败时降级为列表且状态明确。
- 飞书 webhook（测试地址）收到卡片消息；自定义 webhook 收到 JSON；失败有错误记录且可重推。
- 重启后调度继续，`next_run_at` 持久化不重复生成。

## 已知限制

- 报告只覆盖窗口内新发布条目，不做历史回溯生成。
- AI 成本与单条摘要共用同一配额与密钥。
- 飞书 webhook 有平台侧限流（约 100 条/分钟），Rill 侧不做合并重试风暴，只按规则周期推送。
