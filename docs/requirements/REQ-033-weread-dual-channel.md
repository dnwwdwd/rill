# REQ-033 公众号双通道（微信后台 + 微信读书）

- 状态：进行中（本地 httptest 通过；真实微信读书扫码与外部号抓取待验收）
- 优先级：P0
- 日期：2026-11-03
- 关联：[REQ-026](REQ-026-wechat-builtin-core.md)、[REQ-028](REQ-028-wechat-search-and-x-fallback.md)、[BUG-001](../BUGS.md)、DEC-018/DEC-023、[微信读书调研](../research/2026-11-wechat-rate-limit-alternatives.md)

## 1. 背景

2026-07 起微信后台跨账号列表对非自有账号返回 `200013`；BestBlogs 只覆盖 375 个号。用户要求同时保留微信后台通道并新增微信读书通道，按稳定性优先自动选择。已安装 WeRSs 复核后确认其核心也走微信后台接口，不能解决该限制。

## 2. 目标

1. 微信后台通道继续用于当前后台管理的自有账号。
2. 新增微信读书扫码登录通道，用于外部公众号；Cookie AES-GCM 加密落库，不新增 schema。
3. 外部账号流程：
   - `searchbiz` 搜索仍用于解析 fakeid；
   - Rill 由 fakeid 推导 `bookId = MP_WXS_<base64decode(fakeid)>`；
   - 首次抓取幂等加入微信读书书架；
   - 读取 `/web/mp/articles`，正文走 `/web/mp/content`。
4. 双通道选择：
   - 自有账号先微信后台；微信后台限流/失败且微信读书已连接时回退微信读书。
   - 外部账号直接走微信读书；不再请求必然失败的微信后台列表。
   - 微信读书 `-2041` 触发 4 小时通道冷却。
5. 微信读书登录必须扫码：
   - `POST /api/v1/wechat/weread/scan` 返回二维码；
   - `GET /api/v1/wechat/weread/scan/status` 轮询；
   - 二维码 UID 不返回前端，Cookie/登录凭据不写日志。

## 3. 非目标

- 不承诺微信读书全量历史；若 Web 列表不可用，只能退化为最新文章。
- 不自动绕过微信读书验证码。
- 不支持多微信读书账号池。
- 不承诺所有公众号已被微信读书收录；收录可能滞后。

## 4. 验收

- 本地 httptest：
  - 微信读书扫码流程换取加密 Cookie；
  - fakeid 到 bookId 转换；
  - 外部账号在微信后台 `200013` 后回退微信读书，抓取到 1 条并入库；
  - `-2041` 触发微信读书冷却且冷却期不发请求。
- `go test ./...`、`go vet ./...`、race、前端 typecheck/test/build。
- 真机验收：真实微信读书扫码、书架加入、外部公众号列表/正文、验证码处理、Cookie 过期重登。

## 5. 风险

- 微信读书接口非公开，可能变化；`-2041` 需人工在官方客户端/浏览器完成验证。
- 收录不全、更新滞后；不能把该通道描述为“任意公众号稳定方案”。
- Cookie 代表用户微信读书登录态，必须加密、脱敏、可删除。
