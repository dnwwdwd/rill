# REQ-009 全页面 Mock 数据

- 状态：已完成（本地验证）
- 优先级：P2
- 关联：前端开发/视觉验收、[`web/src/api/mock/seed.ts`](../../web/src/api/mock/seed.ts)、[`web/src/api/mock/mockApi.ts`](../../web/src/api/mock/mockApi.ts)
- 事实来源：[web/README.md](../../web/README.md)、[REQ-008](REQ-008-ui-design-system.md)

## 目标

让 `VITE_USE_MOCK=true` 下所有可访问页面都有可操作、可截图的演示数据，不依赖真实后端、外部 Feed、公众号侧车或真实 API Key。

## 覆盖范围

| 页面 / 能力 | Mock 数据 |
| --- | --- |
| 登录 | 公开健康检查成功；任意非空密码可登录 |
| 阅读首页 | 24 个条目；全部/收藏筛选均有内容；未读与来源数据保留在条目和源管理中 |
| 侧栏 | 5 个文件夹、20 个源；每个源至少 1 个条目 |
| 条目详情 | 正文、AI 摘要、译文、收藏/已读状态 |
| 专注阅读 | 同一详情数据、进度条、来源栏、阅读设置 |
| 源管理 | 20 个源、5 个文件夹、正常/需关注/暂停/登录失效状态；现位于设置弹窗的「订阅源」分类 |
| 全源诊断 | 每个源都有 6 个指标、抓取历史与 14 天趋势；至少一个 warn/auth/paused 样本 |
| 设置 · 阅读 | 字体、行宽、行高、主题、主题色、自动已读、阅读位置 |
| 设置 · AI | 地址/模型/密钥状态、摘要样式、额度用量、翻译目标、外发确认 |
| 设置 · 公众号 | 过期登录态、二维码框架、2 个公众号源 |
| 设置 · 备份 | 最近备份、保留份数、恢复提示 |
| 设置 · 安全 | 当前会话、Feed 令牌、安全边界 |
| 添加源 | 网址发现返回 3 个候选；X/公众号 tab 可用 |
| 404 | 独立页面与返回操作 |

## 不做

- 不写入真实 API Key、Cookie、OAuth token 或 Feed token。
- 不改变真实 API、数据库 schema 或抓取行为。
- 不用 mock 伪造已验证的外部源能力；真实源验收仍按 `docs/PROGRESS.md` 的未验证项处理。

## 验收证据

- `mockApi` 的登录、源/文件夹、条目分页、详情、诊断、设置、发现、扫码、备份接口均有实现。
- Playwright 本地检查：
  - 20 个源筛选均有条目（1–2 条/源）。
  - 20 个源诊断页均有 6 个指标、抓取日志和 14 根趋势柱。
  - 设置弹窗 6 个分类（订阅源 / 阅读 / AI / 公众号 / 备份 / 安全）均有分区和控件。
  - 添加源发现 3 个候选；404 页面可见。
- 无 JS 错误；mock 模式不请求真实后端。
