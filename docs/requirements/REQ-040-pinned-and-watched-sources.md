# REQ-040 置顶订阅源与关注源即时提醒

- 状态：已实现（本地验证；真实渠道/浏览器待验收）
- 日期：2026-11-13
- 关联：PRD F-55/F-56、PDD §4.2/§5.2/§9.1、DEC-031

## 目标

1. 在侧栏「订阅源」树顶部提供全局「置顶」区，用户可以把自己关心的源固定到最上方，不跟随原分组显示。
2. 为单个订阅源增加「关注更新」开关。关注源抓取到新条目后，立即通过现有飞书/自定义 Webhook 推送渠道发送提醒；用户可选择每篇一条或每次抓取合并一条，并可选择是否附带 AI 总结。
3. 关注源在侧栏/移动端源列表显示未读 dot，作为应用内提醒。

## 用户决策（2026-11-13）

- 置顶位置：**全局置顶区**，不跟随原分组；置顶源从原分组列表中移出，避免重复。
- 提醒渠道：复用现有飞书 / 自定义 Webhook（`push_channels`）；本轮不接懒猫系统消息、不做浏览器 Web Push。
- 通知聚合：用户按源选择「每篇新文章一条」或「每次抓取合并一条」。
- AI 总结：跟随通知聚合策略；每篇模式生成单篇摘要，合并模式生成批次摘要。AI 未启用或失败时降级为标题列表。

## 范围

### 置顶

- 存储：`settings.reader.pinned_sources`（源 ID 数组），跨设备同步；不新增表/列。
- 交互：订阅源右键菜单增加「置顶 / 取消置顶」；编辑源弹窗也提供同一开关。
- 展示：桌面侧栏在订阅源树顶部渲染「置顶」区；移动端订阅源页同样置顶。置顶源不再出现在原分组/未分组列表中。
- 排序：按 `pinned_sources` 数组顺序；新置顶的源追加到末尾，可用后续拖拽增强。
- 源被删除后，前端过滤失效 ID；后端保存设置时只保留正整数并去重。

### 关注更新

- 入口：
  - 设置 → 自动化 → 「关注订阅源」：集中展示已关注源，可编辑或添加；
  - 侧栏订阅源右键 → 「关注订阅源 / 关注设置」：打开同一独立弹窗；
  - 编辑订阅源表单不再承载关注配置，只保留源基本信息、同步、保留和高级设置。
- 批量操作（2026-11-13）：
  - 「关注订阅源」支持「批量管理」：勾选多个已关注源后，统一打开「批量关注设置」修改提醒方式、AI 总结和推送渠道，或直接取消关注；
  - 添加关注源时支持搜索并多选源，一次应用同一套提醒设置；
  - 提醒方式分段控件按内容宽度展示，不占满整列。
- 存储：写入 `sources.config_json`，字段：
  - `watch_enabled`：是否关注更新
  - `watch_mode`：`each`（每篇一条）或 `batch`（每次抓取合并一条）
  - `watch_ai`：是否附带 AI 总结
  - `watch_channel_ids`：选中的 `push_channels` ID
- API：`Source` 返回上述字段；`PATCH /sources/{id}` 接受同名字段；创建源可选传入。
- 触发：抓取提交成功后，仅对**本次新入库**、且过滤规则后仍可见/未读的条目发送。
- 不触发：首次抓取（避免把历史窗口一次性推送）、全量历史回补、源暂停、过滤规则标记为已读/隐藏的条目。
- 每篇模式：逐条发送，单次抓取最多 20 条，超出部分不再逐条推送（避免 Webhook 风暴），服务端日志记录截断。
- 合并模式：每次抓取最多取 20 条生成一条通知，正文包含源名、条数、标题列表；AI 开启时先给批次摘要。
- 渠道：只使用启用的 `push_channels`；未选择或全部停用时不推送，保留应用内 dot。
- AI：复用现有 AI 配置与用量记录；AI 失败/未配置时自动降级为标题列表，不阻断抓取和推送。
- dot：`watch_enabled && unread_count > 0` 时在源行显示未读 dot；点击源阅读后随未读数消失。

## 非目标

- 不做 WebSub / 源站实时推送；提醒延迟仍取决于该源 `refresh_seconds`。
- 不接懒猫平台 `MessageService`、浏览器 Notification / Web Push。
- 不增加“已读水位 / 上次查看时间”字段；dot 复用现有 unread 状态。
- 不提供通知历史、重推、静默时段或按条限流配置。

## API

- `GET /api/v1/sources`、`GET /api/v1/sources/{id}`：返回关注字段。
- `PATCH /api/v1/sources/{id}`：接受 `watch_enabled`、`watch_mode`、`watch_ai`、`watch_channel_ids`。
- `GET/PATCH /api/v1/settings`：`reader.pinned_sources`。
- 复用 `POST /api/v1/channels/{id}/test` 验证渠道可用性。

## 验收

- 置顶源显示在订阅源树顶部，刷新页面/换设备后保持；原分组不再重复显示。
- 关注源在非首次抓取发现新条目时，按所选模式推送到所选渠道。
- 每篇模式通知带单篇 AI 摘要；合并模式通知带批次摘要；AI 失败时两者均降级为标题列表。
- 首次抓取、回补、过滤隐藏/已读条目不触发提醒。
- 关注源有未读时显示 dot；全部阅读后 dot 消失。
- 未选择渠道或渠道停用时不影响抓取，仅不推送。
- 「关注订阅源」可多选后批量修改提醒设置或取消关注；添加时可一次选择多个源。
- 提醒方式分段控件不拉伸占满整列，推送渠道勾选行高度正常。

## 已知限制

- “立即”受源刷新间隔限制（默认 1800 秒，可选 900–43200 秒）。
- 每篇模式可能产生多条 Webhook；单次抓取硬上限 20 条。
- 合并模式最多取 20 条生成通知，更多新条目只体现在应用内未读数。
- 通知发送失败只写服务端日志，不自动重试；渠道测试复用现有测试入口。
