# REQ-002 微信公众号 sidecar 与扫码

- 状态：进行中
- 优先级：P1
- 关联功能：F-15（公众号登录型）、F-16（登录态管理）
- 事实来源：[PRD.md](../../PRD.md)、[PDD.md](../../PDD.md) §7.4、[RSS-SOURCES.md](../RSS-SOURCES.md) §4
- 功能进度：[PROG-REQ-002-wechat-sidecar](../progress/PROG-REQ-002-wechat-sidecar.md)

## 目标

用户在设置弹窗启用公众号采集，通过 `we-mp-rss` sidecar 扫码登录，添加具体公众号，并把公开文章作为 Feed 收进 Rill；登录态过期时明确暂停、提示重扫，不影响其他源。

## 当前实现

- 设置弹窗有启用开关、sidecar 地址、二维码占位和登录态展示。
- mock 模式有“模拟扫码成功”，只用于界面联调。
- 真实 `POST /wechat/scan` 始终返回 503：未配置 sidecar 时返回 `wechat_sidecar_unavailable`；即使配置了也返回 `wechat_scan_unavailable`，不伪造成功。
- 后端可以接受指向已配置 sidecar 主机的 `wechat` Feed URL，并有 401 登录态处理框架；但自动发现账号和前端添加入口缺失。
- 没有真实 `we-mp-rss` 实机联调，也没有真实文章入库。

## 范围

### 必须

- 配置真实 sidecar 地址并验证连通性。
- 设置弹窗展示真实二维码，轮询扫码结果，成功后写入登录态。
- 能从 sidecar 获取账号/Feed 列表，添加指定公众号；不在主应用保存微信 Cookie。
- 抓取至少 1 篇公开文章，保留原文链接和封面，并按文章 URL 去重。
- 登录态过期时公众号源进入 `auth` 状态并暂停；重扫后恢复。
- sidecar 关闭时其他 RSS 源不受影响。

### 不做

- 不提供无登录抓取路径。
- 不实现搜狗/文章直链批量爬取。
- 不接入 werss / WeWe RSS / 第三方托管。
- 不绕过付费墙、登录墙或私密内容。

## 未决问题

1. `we-mp-rss` 的真实扫码接口、轮询协议、登录态有效期和账号 Feed 枚举方式是什么？
2. 谁负责公众号账号与文章列表：sidecar 管理界面，还是 Rill 前端调用 sidecar API？
3. sidecar 地址由 LPK 注入还是用户配置？是否需要内网访问白名单？
4. 扫码过期、sidecar 重启和登录态失效如何同步到每个公众号源？

- 公众号是 P1；在 sidecar 未联调前，主应用只能展示不可用状态，不得声称已实现。
